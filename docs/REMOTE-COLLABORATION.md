# 异地 Agent 协作

## 范围与验收

Vercel 提供 HTTPS 网页和短请求 API，Supabase 保存共享状态；Codex、Claude Code、DeepSeek Harness 在各自电脑执行。保留已有主人审批后回群的规则。

1. 同一任务只能被一个持有有效租约的 worker 执行；每个 agent 同时最多一个作业。
2. 领取、续租、成果提交立即持久化。响应丢失后重复提交不会重复发成果。
3. 本地先保存结果再回传；网络故障重试回传，不能重新启动已完成的命令。
4. 租约过期可重新领取；旧租约不能交卷。无法保证本地外部副作用只发生一次，执行程序必须自行对外部写入去重。
5. 主人驳回产生新一轮作业；之前轮次不能覆盖新报告。
6. 云端禁用演示凭据、开放注册和服务器执行后端。凭据仅保存在服务端环境或本机忽略目录。

## 实现计划

- `remote-jobs.mjs`：持久化任务/群聊队列、租约、提交去重。
- `worker.mjs`、`worker-executors.mjs`：本地常驻程序和三种 Agent 的非交互接入。
- `cloud-store.mjs`、`api/index.js`、`vercel.json`：无状态部署；共享快照采用 revision 条件写入，冲突后重新处理尚未发送的请求，避免多实例覆盖。
- `supabase/scitag.sql`：仅服务器可访问的状态表与条件写入函数。
- `test-remote.mjs`：真实 HTTP 接口及独立本地进程的集成测试；`npm test` 保留原有测试。

## 边界

首版适合小课题组，云端快照是原有 JSON 模型的兼容迁移，不适合大规模高并发。云端使用短轮询，Agent 在本地运行且应保持联网。先支持报告文本与任务工作目录中的成果；任意二进制文件跨设备传输需另配私有对象存储，不能把本机路径当作已共享文件。

本地执行命令由电脑主人预先配置，服务器不能指定可执行文件或 shell 命令。Codex 使用明确的 sandbox；Claude 使用自己的权限机制；DeepSeek Harness 使用本地 headless profile 的权限设置。
